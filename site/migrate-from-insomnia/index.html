Migrate from Insomnia to Zeno

Zeno reads your Insomnia data directly, so moving takes about a minute and nothing changes in Insomnia. Your requests, environments, chained tokens, scripts and shortcuts come over as they are.

Download Zeno View on GitHub

1. Install Zeno

Download it from the releases page (.deb, .rpm, AppImage, Flatpak, Windows installer, macOS .dmg), or use brew install --cask chmenegatti/tap/zeno or Scoop. Insomnia can stay installed; Zeno only reads its files.

2. Import

  1. In Zeno, open the workspace menu and choose Import….
  2. Click the button that reads your Insomnia data folder. Zeno finds it by itself:
    • Linux: ~/.config/Insomnia
    • Windows: %APPDATA%\Insomnia
    • macOS: ~/Library/Application Support/Insomnia
    If Insomnia is on another machine, export from Insomnia (v4 JSON or v5 YAML) and use Choose files… instead.
  3. Choose the workspaces to bring over in the preview. Keep the vault option checked: passwords, tokens and keys go to Zeno's vault and the YAML only keeps the encrypted value.
  4. Read the list of anything that couldn't be converted (for example a template tag from a plugin you don't have) and click Import.

What comes over

  • Workspaces, folders and requests, in the same order, with the same ids.
  • Base and sub-environments, folder variables and headers, auth inheritance.
  • Auth: Basic, Bearer, API key, OAuth 2.0.
  • Bodies: JSON, XML, text, form, multipart with files, GraphQL. WebSocket and gRPC requests too.
  • Template tags: {{ variable }}, {{ _.variable }} and {% response %} chaining keep working; so do uuid, now, base64, hash, faker and prompt.
  • Pre-request and after-response scripts (insomnia.* is an alias for zeno.*).
  • Your customized Insomnia shortcuts. The defaults are already the same.
  • Insomnia-format plugins: copy them into Zeno's plugins/ folder.

3. Put the workspace in git (optional)

Each request is now a readable YAML file. In the workspace settings choose Move to folder… and pick a folder inside your service's repository: the collection is reviewed in pull requests like the rest of the code, and encrypted secrets can be committed. Run it in CI with zeno run.

What's different from Insomnia

  • There are no tabs: clicking a request replaces what's on screen. Ctrl+P jumps to any request.
  • No account and no cloud sync. To share, keep the workspace in git or use Save to GitHub (your own private repository).
  • SOAP and Socket.IO aren't supported.

Questions or something that didn't import? Ask in Discussions or open an issue with the warning text.

FAQ

Do I need to export from Insomnia first?

No. Zeno reads the installed Insomnia data folder directly. Exports (v4 JSON or v5 YAML) also work.

Will my {% response %} token chaining keep working?

Yes. Zeno uses the same template tag syntax as Insomnia, including {% response %} with its triggers.

Does importing change anything in Insomnia?

No. Zeno only reads Insomnia's files.
