Zeno vs Bruno

Bruno and Zeno share the same idea: collections are files that live in git, with no cloud and no account. They differ in the details, and Bruno has a much larger community.

Where Zeno is different

  • Secrets committed safely, inside the same files. Zeno encrypts tokens inside the YAML with a key in your OS keychain, so you commit one folder and nothing leaks. Bruno keeps secrets out of the shared files instead (local secret variables, .env, or external managers on a paid plan).
  • Built for leaving Insomnia. Zeno reads the installed Insomnia data folder without an export, and keeps Insomnia's template tags ({% response %} chaining, uuid, now…), Insomnia-format plugins and shortcuts.
  • One screen, no tabs. Clicking a request swaps the content.
  • No paid tier. Every feature is in the MIT-licensed app.
  • Go instead of Electron. The OS web view keeps the package at 8–24 MB.

Where Bruno is the better choice

  • Community and maturity. Bruno has tens of thousands of GitHub stars, a large contributor base and commercial support; Zeno is young and maintained by one developer.
  • You need SOAP, WSDL import or external secret managers (HashiCorp Vault, AWS, Azure, GCP).
  • You want the OpenCollection YAML format, which aims to be an open standard across tools.
  • Your team uses Bruno's VS Code extension or its git UI.

FAQ

Do Zeno and Bruno both store collections in git?

Yes. Both keep collections as plain files. Zeno uses one YAML file per request; Bruno uses .bru files or OpenCollection YAML.

How does Zeno keep secrets out of git?

It doesn't need to: secrets are encrypted inside the YAML with a key stored in the OS keychain, so the encrypted values can be committed.

Can Zeno import Bruno collections?

Not directly today. Zeno imports Insomnia, Postman v2.1 and OpenAPI.
